PIPELINE BEHAVIOR

The Jenkinsfile is stored in the GitHub repository.

The Pipeline performs these operations:

1. Checks out the master branch.
2. Runs git lfs pull.
3. Verifies that the .uproject, Unreal Automation Tool, and Butler exist.
4. Builds the project for Win64 Development.
5. Cooks all required content.
6. Stages and packages the game.
7. Archives the packaged output into BuildOutput.
8. Uploads the unpacked Windows package through Butler.
9. Publishes it to the windows-dev itch.io channel.
10. Uses the Jenkins build number as the itch.io user version.
11. Keeps only five Jenkins build records.
12. Prevents concurrent Unreal builds.
13. Uses a 90-minute timeout.

The Pipeline intentionally preserves Binaries, Intermediate files, and Unreal caches between builds. Do not add deleteDir() or automatically erase the whole workspace after every build. Preserving those files reduced the test build from roughly 50 minutes to approximately 3 minutes.

The BuildOutput directory itself is deleted and recreated before each package operation.

WORKING UNREAL BUILD COMMAND

The successful command is equivalent to:

call "C:\Epic\UE_5.8\Engine\Build\BatchFiles\RunUAT.bat" BuildCookRun ^
  -project="%WORKSPACE%\ProjectName.uproject" ^
  -noP4 ^
  -platform=Win64 ^
  -clientconfig=Development ^
  -build ^
  -cook ^
  -stage ^
  -pak ^
  -package ^
  -archive ^
  -archivedirectory="%WORKSPACE%\BuildOutput" ^
  -utf8output ^
  -unattended

The packaged output is placed under:

%WORKSPACE%\BuildOutput\Windows

The top-level executable should be launched, for example:

BuildOutput\Windows\ProjectName.exe

Do not launch the duplicate executable directly from the internal Binaries\Win64 directory when testing the packaged game.

WORKING BUTLER UPLOAD

The successful Butler command is equivalent to:

"C:\Tools\butler\butler.exe" push ^
  "%WORKSPACE%\BuildOutput\Windows" ^
  "itch-username/game-slug:windows-dev" ^
  --userversion "jenkins-%BUILD_NUMBER%"

The unpacked Windows package directory should be uploaded rather than a ZIP. Butler uses differential uploads, so later uploads transfer only changed data.

Butler receives authentication through the Jenkins credential:

environment {
    BUTLER_API_KEY = credentials('itch-butler-api-key')
}

REAL HACKATHON PROJECT SETUP

For the real project:

1. Confirm that it uses Unreal Engine 5.8.
2. Open PowerShell in the directory containing the real .uproject file.
3. Initialize Git using the master branch.
4. Run git lfs install.
5. Add the same .gitignore and .gitattributes rules listed above.
6. Stage the files.
7. Verify that .uasset and .umap files appear in git lfs ls-files.
8. Commit the project.
9. Create an empty public GitHub repository without a generated README, license, or .gitignore.
10. Add the GitHub repository as origin.
11. Push master.
12. Create the real project page on itch.io and initially leave it Draft or Restricted.
13. Copy the tested Jenkinsfile from JenkinsTest into the real repository.
14. Update PROJECT_FILE in the Jenkinsfile.
15. Update ITCH_TARGET in the Jenkinsfile.
16. Keep UE_ROOT set to C:\Epic\UE_5.8.
17. Initially keep ITCH_CHANNEL set to windows-dev.
18. Commit and push the Jenkinsfile.
19. Create a new Jenkins Pipeline-from-SCM job for the real repository.
20. Configure it for the master branch and Jenkinsfile script path.
21. Enable Poll SCM with H/2 * * * *.
22. Run one manual build first.
23. Download the resulting itch.io build and test it on another computer.
24. After the manual test succeeds, allow polling to handle later builds automatically.

The primary Jenkinsfile values that must change are:

PROJECT_FILE = 'RealProject.uproject'
ITCH_TARGET = 'itch-username/real-game-slug'

These can normally remain unchanged:

UE_ROOT = 'C:\\Epic\\UE_5.8'
ITCH_CHANNEL = 'windows-dev'

For development builds, keep:

-clientconfig=Development

For a final public release, consider changing it to:

-clientconfig=Shipping

Development uploads should continue using:

windows-dev

Final approved releases should use a separate channel, such as:

windows

Do not let every development commit overwrite the final release channel.

SECURITY AND SERVER OPERATIONS

- Do not expose Jenkins port 8080 directly to the internet.
- Continue using LAN access and Git polling.
- Do not store GitHub or itch.io secrets in Git.
- Keep the itch.io API key only in Jenkins Credentials.
- Disable sleep and hibernation on the build server.
- Prevent automatic Windows restarts during the hackathon.
- Monitor SSD free space.
- If SSD free space approaches 50 GB, stop builds and clean old workspaces or unused generated data.
- Avoid placing active Jenkins workspaces, Unreal Intermediate files, or DDC on the HDD.
- Finished archives and backups can be copied to the HDD.
- Limit Jenkins to one Unreal build at a time.
- Keep the Jenkins build-discard policy at five builds unless more history is genuinely required.

Push a commit to GitHub master

→ Jenkins downloads Git and Git LFS changes
